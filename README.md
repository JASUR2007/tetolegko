# 🚀 Замер скорости интернета (Network Speed Test)

Консольный скрипт для измерения скорости интернет-соединения путём выполнения серии последовательных HTTP/HTTPS-запросов к удалённому ресурсу (тяжёлому файлу или изображению) и подсчёта метрик передачи данных.

Решение реализовано сразу на двух платформах:
- **Python 3** (`speedtest.py`) — стандартная библиотека (`urllib`, `time`, `argparse`).
- **Node.js** (`speedtest.js`) — встроенный `fetch` и Web Streams API (Node.js 18+).

Обе версии работают **без установки сторонних зависимостей** (zero dependencies).

| Требование | Реализация |

| Скорость скачивания в консоль | Расчёт и вывод в **Mbps** (Мбит/с), **MB/s** (МБ/с) и **MiB/s** |
| Единицы измерения в README | Подробный раздел с математическими формулами и расшифровкой |

## 📊 Единицы измерения

В скрипте и выводе консоли используются следующие единицы:

### 1. Объём данных
* **Байт (B / байт)** — базовая единица измерения переданных данных.
* **Килобайт (KB / КБ)** — $1\text{ KB} = 1024\text{ байта}$ (в таблице для краткости).
* **Мегабайт (MB / МБ)** — $1\text{ MB} = 1024 \times 1024 = 1\,048\,576\text{ байт}$ ($2^{20}$).

### 2. Время
* **Секунды (s / с)** — время выполнения запроса с точностью до миллисекунд (замер через `time.perf_counter()` в Python и `performance.now()` в Node.js).
* **Миллисекунды (ms / мс)** — $1\text{ с} = 1000\text{ мс}$.

### 3. Скорость скачивания
Скорость рассчитывается как отношение общего объёма фактически скачанных данных к чистому времени их загрузки:

$$\text{Speed}_{\text{Bytes/s}} = \frac{\sum \text{Bytes}}{\sum \text{Duration (seconds)}}$$

В итоговой таблице представлены три наиболее признанных стандарта:
1. **Mbps (Мбит/с, Мегабит в секунду)** — общепринятый стандарт интернет-провайдеров и телеком-индустрии:
   $$\text{Mbps} = \frac{\text{Speed}_{\text{Bytes/s}} \times 8}{1\,000\,000}$$
2. **MB/s (МБ/с, Мегабайт в секунду, десятичный СИ)** — привычная для файловых менеджеров и браузеров единица ($10^6$ байт/с):
   $$\text{MB/s} = \frac{\text{Speed}_{\text{Bytes/s}}}{1\,000\,000}$$
3. **MiB/s (МиБ/с, Мебибайт в секунду, двоичный IEC)** — традиционная единица в ОС ($2^{20} = 1\,048\,576$ байт/с):
   $$\text{MiB/s} = \frac{\text{Speed}_{\text{Bytes/s}}}{1\,048\,576}$$

## 🛠 Быстрый старт и запуск

### Вариант A: Python (рекомендуется)

Требуется: **Python 3.8+** (сторонние библиотеки устанавливать **не нужно**).

```bash
# 1. Запуск с параметрами по умолчанию (10 запросов к тестовому файлу Cloudflare 5 МБ)
python speedtest.py

# 2. Замер по своему URL (например, изображение высокого разрешения)
python speedtest.py "https://images.unsplash.com/photo-1451187580459-43490279c0fa?q=80&w=2000"

# 3. Указать количество запросов (флаг -n) и таймаут (флаг -t)
python speedtest.py "https://speed.cloudflare.com/__down?bytes=10000000" -n 5 -t 15

# 4. Включить обход кэша промежуточных прокси (--no-cache)
python speedtest.py -n 10 --no-cache
```

### Вариант B: Node.js

Требуется: **Node.js 18+** (`npm install` делать **не нужно**).

```bash
# 1. Запуск с параметрами по умолчанию
node speedtest.js

# 2. Замер по своему URL
node speedtest.js "https://images.unsplash.com/photo-1451187580459-43490279c0fa?q=80&w=2000"

# 3. Указать количество запросов и таймаут
node speedtest.js -n 5 -t 15

# 4. Через npm скрипт
npm start
```

## 🔍 Архитектурные детали («Понимание каждой строчки кода»)

1. **Строгая последовательность**:
   Запросы намеренно не распараллеливаются (`asyncio.gather` / `Promise.all` не используются). Применяется синхронный цикл, где запрос `i + 1` инициируется только после полного получения последнего байта запроса `i`. Это исключает конкуренцию за полосу пропускания между параллельными потоками скрипта.
2. **Потоковое чтение (Streaming chunks)**:
   Тело ответа читается буфером фиксированного размера (64 КБ) через `response.read(chunk_size)` в Python и `reader.read()` в Node.js. Это предотвращает переполнение оперативной памяти (OOM) даже при тестировании на файлах объёмом 500 МБ+.
3. **Высокоточные таймеры**:
   Используются монотонные аппаратные таймеры `time.perf_counter()` и `performance.now()`. В отличие от `time.time()` или `Date.now()`, они не подвержены дрейфу системных часов и синхронизациям NTP.
4. **Обработка ошибок и валидация**:
   Скрипт проверяет схему URL (`http`/`https`), валидирует сетевые ошибки (`URLError`, `HTTPError`, `AbortError`), тайм-ауты и корректно учитывает только успешно завершенные запросы в статистике.
