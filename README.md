# 🚀 Замер скорости интернета (Network Speed Test)

Консольный скрипт для измерения скорости интернет-соединения путём выполнения серии последовательных HTTP/HTTPS-запросов к удалённому ресурсу (тяжёлому файлу или изображению) и подсчёта метрик передачи данных.

Решение реализовано сразу на двух платформах:
- **Python 3** (`speedtest.py`) — стандартная библиотека (`urllib`, `time`, `argparse`).
- **Node.js** (`speedtest.js`) — встроенный `fetch` и Web Streams API (Node.js 18+).

Обе версии работают **без установки сторонних зависимостей** (zero dependencies).

---

## 📋 Требования задания и реализация

| Требование | Реализация |
|---|---|
| Принимает адрес (URL) | Передаётся аргументом командной строки (по умолчанию: тестовый файл Cloudflare CDN ~5 МБ) |
| 10 последовательных запросов | Строгий синхронный цикл: запрос $i+1$ инициируется только после полного закрытия стрима запроса $i$ |
| Дожидается полного ответа | Потоковое чтение чанками по 64 КиБ с валидацией целостности по заголовку `Content-Length` |
| Защита от искажений сжатия | Передача `Accept-Encoding: identity` и проверка `Content-Encoding`, чтобы измерять реальные сетевые байты |
| Контроль общего таймаута | Параметр `-t` ограничивает **полное время выполнения запроса**, а не только простой сокета |
| Среднее время запроса | Расчёт суммарного и среднего времени в секундах и миллисекундах |
| Общий объём данных | Подсчёт байт каждого ответа с корректным разделением двоичных (MiB) и десятичных (MB) единиц |
| Скорость скачивания в консоль | Расчёт и вывод в **Mbps** (Мбит/с), **MB/s** (МБ/с) и **MiB/s** |
| Валидация параметров и exit code | Ненулевой код возврата (`exit code 1`) при сбое всех запросов; строгая валидация аргументов (`-n > 0`, `-t > 0`) |

## 📊 Единицы измерения

В скрипте и выводе консоли строго разделяются стандарты **IEC (двоичные приставки)** и **SI (десятичные приставки)**:

### 1. Объём данных
* **Байт (B / байт)** — минимальная базовая единица переданных данных.
* **Кибибайт (KiB / КиБ)** — $1\text{ KiB} = 2^{10} = 1024\text{ байта}$ (стандарт IEC).
* **Мебибайт (MiB / МиБ)** — $1\text{ MiB} = 2^{20} = 1024 \times 1024 = 1\,048\,576\text{ байт}$ (стандарт IEC).
* **Мегабайт (MB / МБ)** — $1\text{ MB} = 10^6 = 1\,000\,000\text{ байт}$ (десятичный стандарт SI).

В таблице замеров и выводе размеров используется стандарт IEC (`KiB`, `MiB`), а в итоговой сводке дополнительно приводится размер в десятичных `MB` и точное число байт.

### 2. Время
* **Секунды (s / с)** — время выполнения запроса с точностью до миллисекунд (замер через монотонные таймеры `time.perf_counter()` в Python и `performance.now()` в Node.js).
* **Миллисекунды (ms / мс)** — $1\text{ с} = 1000\text{ мс}$.

### 3. Скорость скачивания
Скорость рассчитывается как отношение общего объёма фактически скачанных данных к чистому времени их загрузки:

$$\text{Speed}_{\text{Bytes/s}} = \frac{\sum \text{Bytes}}{\sum \text{Duration (seconds)}}$$

В итоговой таблице представлены три метрики:
1. **Mbps (Мбит/с, Мегабит в секунду)** — общепринятый стандарт интернет-провайдеров и телеком-индустрии:
   $$\text{Mbps} = \frac{\text{Speed}_{\text{Bytes/s}} \times 8}{1\,000\,000}$$
2. **MB/s (МБ/с, Мегабайт в секунду, десятичный SI)** — стандарт для браузеров и файловых систем ($10^6$ байт/с):
   $$\text{MB/s} = \frac{\text{Speed}_{\text{Bytes/s}}}{1\,000\,000}$$
3. **MiB/s (МиБ/с, Мебибайт в секунду, двоичный IEC)** — традиционная системная единица ($2^{20} = 1\,048\,576$ байт/с):
   $$\text{MiB/s} = \frac{\text{Speed}_{\text{Bytes/s}}}{1\,048\,576}$$

## 🛠 Быстрый старт и запуск

### Вариант A: Python (рекомендуется)

Требуется: **Python 3.8+** (сторонние библиотеки устанавливать **не нужно**).

```bash
# 1. Запуск с параметрами по умолчанию (10 запросов к тестовому файлу Cloudflare 5 МБ)
python speedtest.py

# 2. Замер по своему URL (например, изображение высокого разрешения)
python speedtest.py "https://images.unsplash.com/photo-1451187580459-43490279c0fa?q=80&w=2000"

# 3. Указать количество запросов (флаг -n) и общий таймаут на запрос (флаг -t)
python speedtest.py "https://speed.cloudflare.com/__down?bytes=10000000" -n 5 -t 15

# 4. Включить обход кэша промежуточных прокси (--no-cache)
python speedtest.py -n 10 --no-cache
```

### Вариант B: Node.js

Требуется: **Node.js 18+** (`npm install` делать **не нужно**).

```bash
# 1. Запуск с параметрами по умолчанию
node speedtest.js

# 2. Замер по своему URL
node speedtest.js "https://images.unsplash.com/photo-1451187580459-43490279c0fa?q=80&w=2000"

# 3. Указать количество запросов и таймаут
node speedtest.js -n 5 -t 15

# 4. Через npm скрипт
npm start
```

## 🔍 Инженерные детали реализации

1. **Контроль полноты загрузки по `Content-Length`**:
   Если сервер возвращает заголовок `Content-Length`, скрипт сверяет фактическое количество вычитанных байт с объявленным значением. При преждевременном разрыве соединения или усечении ответа запрос помечается как ошибочный (`Неполный ответ: получено X из Y байт`), не искажая статистику скорости.
2. **Исключение искажений от сжатия (`Accept-Encoding: identity`)**:
   По умолчанию многие клиенты отправляют `Accept-Encoding: gzip, br`, а затем распаковывают ответ. Если по сети передано 100 байт gzip, а в память распаковано 100 000 байт, расчёт скорости по распакованным данным дал бы фиктивное завышение в 1000 раз. Скрипт явно запрашивает `Accept-Encoding: identity` и валидирует заголовок ответа, обеспечивая замер именно физической скорости передачи по сети.
3. **Общий дедлайн запроса (`-t / --timeout`)**:
   Таймаут ограничивает не просто паузу между пакетами сокета, а суммарную продолжительность всего запроса (DNS + TCP-рукопожатие + TLS + приём всех байт). По истечении дедлайна запрос прерывается с ошибкой превышения времени.
4. **Потоковое чтение фиксированным буфером (64 КиБ)**:
   Тело ответа считывается через поток (`stream reader` / `response.read(chunk_size)`), что исключает аллокацию гигабайтных массивов в RAM при тестировании крупных файлов.
5. **Валидация аргументов и коды возврата**:
   Некорректные аргументы (например, `-n 0` или неизвестные флаги) пресекаются на этапе парсинга с информативным сообщением об ошибке. Если ни один запрос не завершился успешно, скрипт завершает работу с кодом `exit 1` (для интеграции в CI/скрипты).
